# SeenSnap product completion — November 13, 2026

Target: https://seensnapalpha.netlify.app/ with the existing seensnap-staging Cloud Run API and Cloud SQL database. Preserve the configured Concierge provider/model. Backend rollout must succeed before frontend release.

## Implemented in this release

- **SceneDNA v2:** separate regularized preference fit from metadata confidence. Count evidence only for attributes present in the candidate; unseen actors no longer borrow confidence from unrelated ratings. Unknown attributes remain neutral in fit, so dropping a genre cannot improve a candidate's score. Remove the second whole-score shrink toward 50. Keep the five-rating and minimum-coverage display gates. Return `learning_reason` so established accounts see “Limited match data” when a particular title lacks evidence. Cache identical feature projections only within one owner-scoped scoring request. No synthetic percentage floor or popularity boost; the result is a preference match, not a calibrated enjoyment probability. Session algorithm version changes with the score version, so old discovery cursors refresh safely.
- **Trailers:** monitor actual playback progress after YouTube readiness on web and native. Web retries a stalled play request muted once, then provides a visible retry/next-title route. Deliberate pauses and inactive cards do not trigger recovery. Web retry retains the last observed playback position. Preserve existing 16:9 sizing and native full-screen behavior. Audible autoplay remains subject to browser/device policy.
- **For You and title performance:** return usable local recommendations immediately instead of blocking while filling an arbitrary poster quota from TMDB. Bound cold-start requests to one page per requested media and a shorter upstream timeout; genre-constrained retrieval uses TMDB Discover genre IDs. Reuse fresh title metadata, gallery data, and public related-title candidates. No cross-user recommendation cache.
- **More Like This:** retrieve TMDB-related candidates, keep source-title relevance ahead of taste ordering, and remove known dislikes. Optional authentication preserves public title-link access. Upstream failure no longer turns an otherwise available title detail response into an error.
- **Concierge:** suggested prompts start a fresh search rather than silently inheriting the prior search's filters. Typed follow-ups still retain constraints. Recognize the actual “Help me choose from one of my saved lists” prompt as a hard collection constraint, including plural lists, and recognize “my selected streaming services.” Preserve existing five-result relevance review, list ownership, provider/country validation and replay/continuation logic.
- **Continuous Swipe:** include real followed-user saves and active Watch Team titles when they satisfy the current genre, media, release, region and exclusion rules. Current provider data can qualify a source title. Keep the release-age mix and the shared SceneDNA score. Recheck private-source labels on cursor replay; private lists, blocked users and inactive/archived teams cannot supply these labels.
- **Onboarding/mobile:** share the dominant-axis gesture resolver with main Swipe, claim drags rather than taps, prevent gesture motion during a committed action, update queue refs synchronously, and release the action even if an animation callback is lost. Rating actions stack on narrow or enlarged-text screens; the existing scrollable 1–10 editor remains shared across surfaces.
- **Notifications:** aggregate unread likes for the same post over 24 hours, deduplicate actors, and avoid duplicate outbox entries per notification/device. Direct comments/messages remain separate. Use timestamp-plus-ID pagination so simultaneous notifications are not skipped. Existing open-time audience checks remain in place.
- **Shared links:** title, list, profile and team invitation links target the deployed Netlify application by default. `EXPO_PUBLIC_SHARE_BASE_URL` and backend `SHARE_BASE_URL` remain configurable. Existing audience checks, revoked tokens, typed title identities and sign-in return paths remain authoritative.
- **Premium:** dedicated Settings entry and benefits/membership page; clear server-confirmed beta access without fake prices or purchase buttons. Verified purchase grants can open the relevant store management options. Overlapping grants now expire only when the last grant ends; an indefinite beta grant does not inherit a purchased grant's earlier expiry. Account changes clear the prior entitlement snapshot.
- **Legal destinations:** replace hard-coded .com Terms/Privacy links with the requested .app destinations, configurable via `EXPO_PUBLIC_TERMS_URL` and `EXPO_PUBLIC_PRIVACY_URL`. Legal content itself has not been invented or approved.

## Validation and live observations

Regression coverage includes candidate-specific score evidence, positive/negative taste ordering, request-scoped caches, notification aggregation and stable pagination, overlapping Premium grants, source-relevant related titles, private-source label revocation, fresh metadata reuse, suggested-prompt versus follow-up behavior, the compact ten-option rating editor, stalled playback and deliberate pause behavior. GitHub CI runs the complete PostgreSQL-backed suite, migration gate, client tests, TypeScript, Expo web export and deployment safety checks.

Before this release, the signed-in production Concierge returned five titles for “Comedy movies under 90 minutes on Netflix.” “Different options” returned five new titles and retained those constraints. The live “From my saved list” suggestion incorrectly continued that search; this release fixes both the UI routing and deterministic plural-list recognition. These observations do not replace acceptance against the new backend.
