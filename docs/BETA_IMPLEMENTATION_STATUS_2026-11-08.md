## Implemented in this branch

- **TMDB integrity:** sparse search/discovery/credit results preserve richer title metadata. Genre IDs resolve against the appropriate movie/TV map; full detail refreshes have explicit replacement semantics and provenance timestamps. Movie and TV IDs remain separate throughout mixed-media deduplication.
- **Concierge:** strict typed intent validation, one schema-repair attempt, exact person resolution with verified credits, request-specific metadata/provider hydration, and a separate evidence-based relevance review for every returned title. The next four posters use the same relevance threshold as the hero. No unrelated filler is introduced to make five results.
- **Personal collection search:** specific Next Watch intent takes precedence over generic custom-list parsing. Authorized collection membership is queried in full, known hard mismatches are removed before the candidate budget, watched titles are excluded where appropriate, and previously shown alternatives are excluded before refill. The model receives a bounded taste summary; it does not receive another user's private collections.
- **Concierge recovery:** shorter/longer/provider refinements preserve the other active constraints. Undo restores a saved snapshot without another generation. Refinements have optimistic versions, replay keys, stale-write checks, and an owner-only current-decision endpoint. Provider failures and unavailable metadata have distinct failure states. Configuration details are no longer leaked in end-user error strings. Client timeouts accommodate model/TMDB work and the original query remains editable.
- **Ratings:** legacy rating and Watched routes now use the canonical transition service. Rating submission marks Watched and removes Next Watch membership, while custom lists and manual ranks are preserved. Clearing a score preserves Watched. Per-user database locks serialize competing canonical mutations; stale rating versions are rejected.
- **Rating UI:** one shared editor replaces narrow inline number rails. It loads the current server version before editing, displays all ten choices in a responsive grid, uses at least 44-by-48 targets, permits vertical scrolling, respects safe-area padding, and preserves a draft when another device wins a rating conflict.
- **Rankings:** removes the database's obsolete 100-title constraint and the append/add 500-title cap. All ranked titles can be reached through paginated reads. Manual moves use absolute server positions and serialize per user. Append reports the actual number added; rebuild drafts include all rated titles. My Picks continues loading additional collection pages, reports exact Watched union counts and full-collection unplaced counts, and opens Watch Team selection directly. Dead personal Heart/Comment actions are removed.
- **Social/stories/lists:** taste matches, stories and feed controls scroll with the feed. Story editing and viewing share one modal and refresh their backing data after changes. Story deletion and list deletion have confirmations that work on web and native. List removal controls have larger touch targets. Appending ratings also uses a cross-platform confirmation.
- **Onboarding:** Up records Watched and opens the same rating sheet; Down records Watched/disliked; Right means Interested; Left means Pass; unknown-title skip is neutral. The goal is five ratings, with optional early exit. Progress advances only after accepted writes. Completion is cached per account only after server success. Profile/preference failures remain visible and retryable. Country is visible/editable, subscription labels do not imply authenticated streaming accounts, a versioned owner-only draft retains step/name/handle/country/services on the server and device, and the content scrolls within a centered layout with height-aware posters.
- **Verification workflow:** GitHub Actions runs PostgreSQL migrations and regression tests, TypeScript checking, and the Expo web export on pull requests.

## Continuation batch: privacy, notifications and discovery

- **List and Social access:** old share tokens now check the list's current audience and block relationships. Audience reductions revoke old links permanently. Displaying a Social post cannot mint a share token. List-post audiences cannot exceed their source list. Likes/comments, legacy feeds and profile activity use the current visibility rules; private team events stay out of Social, including the author's own feed. Named social-save recommendations require a currently visible list and a real, unblocked followed user.
- **Profiles:** public profile/taste/ranking entry points enforce profile audience and block settings. Private saved-title obsessions no longer appear on someone else's profile; its poster strip uses actual ranked favorites. Public rankings paginate beyond 100 in the owner's order, with an exact total. Public-list summaries check current list visibility.
- **Notifications:** opens resolve the current canonical entity and permissions on the server, not an arbitrary stored URL. A real post route displays the referenced Social post. Deleted/inaccessible posts, missing conversations and inactive/archived teams return a recoverable unavailable state with a path back to Social. Both push and in-app opens use this resolver; notification loading resets across accounts.
- **Swipe/Preview continuation:** both surfaces use one eligibility service, media-specific TMDB discovery/genre IDs, region/streaming criteria, current saved/ranked/watched/rated exclusions, and owner/filter/region-bound database cursors. Pending and delivered IDs persist independently of page offsets. Retries replay the last page and recheck current exclusions. Upstream failure is retryable rather than reported as catalog exhaustion. The client preserves server order, ignores stale responses and prefetches continuation without the 20/25-action stop or local reshuffle/recycle fallback.
- **Discovery decisions:** a durable ledger survives the old 500-record taste-history pruning. Left is suppressed for exactly 100 subsequent accepted discovery actions; onboarding, retries and undone decisions do not advance that count. Up marks Watched and offers rating; Down marks Watched/disliked without inventing a score; Right records interest without saving. Watched updates and the decision receipt commit atomically. Undo preserves newer rating/status edits and unrelated list memberships. Migration `20261108_0038` backfills only retained, non-onboarding legacy actions; already-pruned history cannot be reconstructed.
- **Ordering:** discovery uses calendar release-age bands with cumulative 50/30/15/5 allocation when supply permits, and redistributes among available bands when it does not. Within each band it now uses the shared, versioned ten-dimension SceneDNA scorer described below. Cursor replies report allocation and shortfall evidence.
- **Mobile discovery controls:** filters are stored per account and shared between Swipe and Preview; TV uses its own supported genre choices. Filters collapse after the first accepted swipe, with a control to reopen them. Swipe help and explicit Watched/Disliked controls use the current semantics. Save, Send and Watch Team open their actual sheets directly; provider buttons open the appropriate web/app destination. Up waits for server success before opening the shared rating sheet. Failed writes retain the card and can be retried.
- **Preview playback and collections:** both video dimensions derive from 16:9 and the measured viewport. The web player waits for YouTube readiness before applying sound, preserves its instance while resizing or changing mute, and pauses behind details/actions or off-tab. Browser autoplay restrictions have a visible Play instruction. Ranked/list previews fetch successive source pages and retain owner order beyond 100; bounded parallel video resolution distinguishes upstream failure from a missing trailer. The repeated fixed-total counter is removed.

## Continuation batch: Concierge recovery and deeper search

- **Initial request recovery:** migration `20261108_0039` adds owner/key-bound request receipts. A successful retry returns the same decision without another model call or allowance charge. A changed payload cannot reuse that key. Short user-row locks serialize claims and free-plan cap checks; model work runs after the claim commits. A lost worker's 150-second lease can be explicitly resumed, and its stale response cannot overwrite the resumed request.
- **Allowances:** failed and empty searches release their reservation. Expired reservations are reclaimed. The first successful continuation of an empty search consumes its original slot; further turns do not consume another. Beta Premium remains uncapped, while the future free-plan cap is enforced under concurrent submissions.
- **Deeper retrieval:** reviews candidates in batches of 24, up to six batches per turn, with persistent pending IDs, checked matches, evidence signatures and TMDB page progress. Keep looking and Different options reuse that state when constraints are unchanged. Current list membership, Watched exclusions and hard constraints are rechecked. Every candidate must receive an explicit relevance assessment; every displayed title clears the same threshold. Relevance sorts before personal compatibility. Stopping for time or work limits does not claim the catalog is exhausted.
- **More like selected:** refinements use the selected canonical title ID plus its actual metadata, including when movie and series names collide. A number-one reference in the original query no longer overrides a later selected anchor. Deterministic refinements skip redundant intent interpretation.
- **Recovery UI:** owner-scoped request keys and query/list drafts survive reload for up to 24 hours; no session token is stored in the recovery draft. A retry checks the receipt before submitting again. In-flight searches have a check/resume message; stale account/request responses are ignored. Transient refinement failures retain the current results and version. All requested results are accessible in a horizontal poster strip, with four visible on a compact screen. Concierge Send, Watch Team and Rate open their respective actions directly.
- **Operational evidence:** a request-local 75-second cooperative budget checks stages and caps network timeouts. Safe JSON logs include server request ID, stage durations, outcome, result count and attempt, without raw prompts/provider responses or credentials. This is not a background job queue or a strict wall-clock cancellation guarantee; see remaining work below.

- **Privacy and races:** blocked/private/deactivated profiles are filtered from people discovery and relationship lists. Named compatibility evidence requires mutually visible ranked favorites, not private ratings. Compatibility/team analytics re-evaluate rather than retaining a day-old evidence snapshot. Username writes match availability validation and serialize competing case-insensitive claims. Stale unread-count/account responses are ignored.

## Continuation batch: SceneDNA and Discover collections

- **Shared title compatibility:** implements the brief's versioned ten-dimension beta baseline: exemplars 28%, genres 20%, actors 12%, decade 10%, format/language 7% each, directors 6%, writers 4%, services/studios 3% each. Each canonical title contributes once; numeric ratings override weaker actions, 5–6 are neutral, unrated Watched/Pass are neutral, Right is weak interest, and manual rank adds at most 20% to positive evidence. - **Consistent surfaces:** active For You, Swipe/Preview, Concierge relevance tie-breaking, legacy mode ordering and owner-only title-detail compatibility use the same base scorer. Concierge remains relevance-first. Batched badge reads are scoped to the current account; accepted rating/list/rank/swipe/preference writes invalidate scores, and late reads cannot repopulate a changed account or evidence cache. Recommendation presentation ordering does not alter the displayed base compatibility.
- **TV For You:** media constraints apply before local candidate retrieval, with typed TMDB expansion for a thin catalog. Controlled users with comedy versus documentary preferences receive different TV recommendations even with a much larger popular-movie pool. Cold-start copy is explicit. The For You continuation snapshots available candidate IDs so rating or saving a title cannot shift page offsets and silently skip another title.
- **Durable corrections:** migration `20261108_0042` retains action version and influence-disabled state in the durable discovery ledger, including a backfill from retained history. ## Continuation batch: private story history and discovery recovery

- **Your stories:** Social separates “Your stories” from “Add story,” and Settings also links to private history. All, Active and Archived views paginate through retained stories with a stable timestamp/ID cursor. Owners can reopen full captions/dates and delete active or expired stories with confirmation. - **Discovery restart recovery:** device storage retains account/surface-bound queue IDs, filters and a server cursor. Before rendering, the owner-only resume endpoint checks the source session, region, genre, media, availability mode, current exclusions and accepted decisions. It recovers one prefetched page lost before device storage, preserving order without repeating a confirmed swipe. Invalid, expired or substantially outdated snapshots start fresh. Storage failure does not prevent browsing. This applies to discovery queues; explicit private-list/ranking playback performs current source reads and is not stored as a local private collection snapshot.
- **Swipe detail face:** poster taps show scrollable synopsis, SceneDNA, cast where available, service links and a return-to-poster control.
